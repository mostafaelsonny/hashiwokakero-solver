## الأقسام المطلوبة

### 1. الـ JSON اللي الواجهة بتطلّعه (Puzzle)

The puzzle editor represents the grid and its elements using the following JSON schema:
```json
{
  "dimensions": {
    "rows": 7,
    "cols": 7
  },
  "islands": [
    { "id": "i1", "row": 0, "col": 2, "value": 3 },
    { "id": "i2", "row": 0, "col": 6, "value": 4 }
  ],
  "bridges": [
    { "from": "i1", "to": "i2", "type": 1, "direction": "horizontal" }
  ],
  "algorithm": "Backtracking"
} 

2. توليد الـ IDs (Island IDs Generation)
الفكرة بتاعتها إن أنا بدي كل كود أو اسم حاجة Unique لكل Island موجودة عندي عشان نعرف نميزها وأقدر أتتبعها بسهولة.

دي بتتعمل بـ Auto Increment Counter بتبقى متخزن عندي في الكود عادي جداً بيبدأ مثلاً بـ Counter واحد.

كل ما باجي أدوس على مكان في الشبكة بتحط فيه جزيرة، البرنامج بياخد رقم وبيلزقه في الـ i.

بعدين العداد بيفضل يزيد لوحده Counter Plus Plus لحد ما تحط جزيرة تانية تاخد رقم جديد.

وبتتولد وبتتربط مع الـ Grid Coordinate إن كل جزيرة لما تيجي تعمل Object في الـ JSON بيتحفظ مكانها Row و Column وبتاخد بقى الـ ID عشان تربط مع الـ Column.

فايدة الـ ID إيه؟ إن أنا لما آجي أعمل جسر أو حاجة أقدر أوصل أسرع وأبقى عارفة أنا ماشية مع إيه.

3. التحقق من المدخلات (Input Validation)
عندي تلات حالات في الـ Input Validation: نفس الخلية، خارج الشبكة، والقيم المسموح بها.

نفس الخلية: الـ Rules بتقول لأ، ممنوع لو جيت ضيفت أكتر من جزيرة في نفس الـ Row والـ Column مع بعض.

خارج الشبكة: دي إني بمنع أي حد إن هو يضيف أي عنصر بره أبعاد الـ Grid اللي أنا محددها له أساساً.

القيم المسموحة: إني بقول للبرنامج إن أرقام الجزر بتكون من 1 لـ 8، وأي حاجة غير كده مش هينفع خالص.
