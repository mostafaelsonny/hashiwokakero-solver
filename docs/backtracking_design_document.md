# Backtracking Design Document — Hashiwokakero Solver

## 1. الفكرة العامة (Overview)
خوارزمية البحث العكسي (Backtracking) هي استراتيجية منهجية لاستكشاف مساحات الحلول الخاصة بلعبة الـ Hashiwokakero. تعتمد الفكرة على تجربة عدد الجسور تدريجياً لكل جسر مرشح ($0, 1, 2$)، والتحقق المبكر من صحة المسار (Pruning). إذا أدى الاختيار إلى مخالفة القواعد، يتم التراجع فوراً (Backtrack) لتوفير الوقت وتجربة مسار آخر، وصولاً إلى الحل الصحيح الذي اجتاز الحَكَم النهائي (`validate_solution`).

## 2. تمثيل الحالة (State Representation)
الـ State أو الحالة أثناء البحث تتضمن:
- **`edge_assignments`**: قاموس يحفظ القيمة الحالية لكل جسر مرشح (`"E1": 1, "E2": 0, ...`).
- **`current_degrees`**: حساب الجسور الحالية المرتبطة بكل جزيرة بناءً على الاختيارات المتاحة حتى هذه الخطوة.
- **`current_index`**: مؤشر الجسر المرشح جاري معالجته في الشجرة.

## 3. ترتيب المتغيرات (Variable Ordering)
- يتم اعتماد الترتيب الثابت للجسور المرشحة كما وردت في ملف اللغز الأساسي: ($E_1, E_2, E_3, \dots, E_n$).
- تم تأجيل التحسينات المتقدمة (مثل ترتيب الجسور الأكثر تقييداً أولاً) لما بعد إثبات عمل النسخة الأساسية.

## 4. الفحص الجزئي والتقليم (Partial Validation & Pruning)
أثناء بناء الشجرة، يتم تنفيذ الفحص الجزئي بعد كل اختيار لتقليل مساحة البحث:
1. **التحقق من الدرجات الجزئية:** لا توجد جزيرة تجاوزت الحد الأقصى أو الرقم المطلوب (`required_bridges`).
2. **التقاطعات:** منع أي جسرين متقاطعين من امتلاك قيمة $> 0$ في نفس الوقت (عبر S1-05).
3. **قاعدة التقليم (Pruning Rule):** 
   - *الشرط:* مجموع الجسور الحالية للجزيرة + أقصى سعة متبقية للجسور غير المحددة المرتبطة بها يجب أن يكون $\ge$ الرقم المطلوب (`required_bridges`). 
   - *الإجراء:* إذا كان المجموع أقل، يتم التراجع فوراً (`Backtrack`) لأن الوصول للحل بات مستحيلاً من هذا المسار.

## 5. الفحص النهائي (Final Validation)
- يتم استدعاء دالة **`validate_solution` (S1-07)** **فقط** عندما تصل الخوارزمية إلى ورقة الشجرة (أي بعد تحديد قيم كل الـ Edges).
- يتم في هذه الخطوة فحص اتصال الشبكة بالكامل (`find_connected_components` لتأكيد وجود مكوّن واحد فقط) والتأكد من مطابقة الشروط بنسبة 100%.

## 6. شروط الإيقاف (Termination Conditions)
1. **إيجاد الحل:** إذا حقق الحل تقرير `valid = True`، يتم حفظه وإيقاف البحث (أو الاستمرار لإيجاد كافة الحلول حسب الحاجة).
2. **استنفاد الاحتمالات ("No Solution Exists"):** إذا تم فحص كافة مسارات الشجرة وانتهت من غير إيجاد حل صالح.
3. **تجاوز الحدود ("Search Limit Reached"):** إيقاف البحث في حال تجاوز الحد الأقصى المسموح به لعدد الحالات المفحوصة (`Max States`) أو الوقت المستغرق، لمنع الدوران اللانهائي في الألغاز المعقدة.

## 7. الإحصائيات المسجلة (Performance Metrics)
سيتم تتبع القياسات الآتية لتقييم كفاءة البحث والمقارنة مستقبلاً مع الخوارزميات الجينية (GA & MA):
- **Execution Time:** وقت التنفيذ بالثواني.
- **Explored States:** إجمالي عدد الحالات أو العقد التي تم زيارتها في الشجرة.
- **Backtrack Count:** عدد مرات التراجع (Pruning / Backtracking events).

## 8. الكود التخيلي (Pseudocode)

```python
def solve_backtracking(puzzle_islands, candidate_bridges):
    solutions_found = []
    current_state = {b.id: 0 for b in candidate_bridges}
    
    def backtrack(index):
        # شرط الأساس: لو خلصنا كل الـ Edges، نعمل فحص نهائي
        if index == len(candidate_bridges):
            solution_obj = Solution(current_state)
            report = validate_solution(puzzle_islands, candidate_bridges, solution_obj)
            if report["valid"]:
                solutions_found.append(solution_obj.copy())
                return True  # أو تكريراً للبحث عن الكل
            return False

        edge_id = candidate_bridges[index].id
        
        # تجربة القيم الممكنة لكل جسر: 0, 1, 2
        for value in [0, 1, 2]:
            current_state[edge_id] = value
            
            # فحص جزئي وتقليم (Pruning)
            if is_partial_valid_and_promising(puzzle_islands, candidate_bridges, current_state):
                if backtrack(index + 1):
                    return True  # لو وجدنا الحل المطلوب
                    
            # التراجع وإلغاء الاختيار
            current_state[edge_id] = 0
            
        return False

    backtrack(0)
    return solutions_found
```

## 9. توظيف الـ Core Engine (دوال S1-03 إلى S1-07)
توزيع وتوظيف دوال المشروع السابقة داخل خوارزمية الـ Backtracking يتم بالشكل التالي:
- **S1-03 (Candidate Edges / CandidateBridge):**
  - *متى تُستخدم؟* في بداية تشغيل الخوارزمية (Initialization).
  - *الدور:* تعريف قائمة الجسور المرشحة المتاحة وتحديد المتغيرات ($E_1 \dots E_n$) التي ستتعامل معها شجرة البحث.
- **S1-04 (Degree Validator / check_degrees):**
  - *متى تُستخدم؟* أثناء البحث (`Partial Validation`) بعد كل خطوة اختيار.
  - *الدور:* التحقق من أن مجموع الجسور المؤقتة لكل جزيرة لم يتجاوز الرقم المطلوب، وتطبيق قاعدة التقليم (`Pruning`) لاستبعاد المسارات المستحيلة مبكراً.
- **S1-05 (Crossing Detector / detect_crossings):**
  - *متى تُستخدم؟* أثناء البحث (`Partial Validation`).
  - *الدور:* فحص ما إذا كان الاختيار الحالي أدى إلى تقاطع جسرين بقيمة أكبر من الصفر ($>0$)، وحال حدوث ذلك يتم رفض الفرع فوراً.
- **S1-06 (Connectivity Checker / find_connected_components):**
  - *متى تُستخدم؟* ضمنياً كجزء أساسي من الحَكَم النهائي في نهاية الشجرة.
- **S1-07 (Solution Validator / validate_solution):**
  - *متى تُستخدم؟* فقط عند الوصول لنهاية الشجرة (`Base Case / Leaf Node`) عندما يحصل كل جسر على قيمته النهائية.
  - *الدور:* تعمل كحَكَم نهائي شامل (الدرجات، التقاطعات، القيم، والاتصال) لإعلان ما إذا كان الحل صالحاً حقاً (`valid = True`).

## 10. تتبع يدوي (Manual Trace) على لغز P1
- **تفاصيل لغز P1:**
  - الجزر: $A, B, C, D$ (مطلوب 2 لكل جزيرة).
  - الجسور المرشحة: $E_1(A-B)، E_2(A-C)، E_3(B-D)، E_4(C-D)$.
  - الترتيب المتبع: $E_1 \rightarrow E_2 \rightarrow E_3 \rightarrow E_4$.

| الخطوة | الاختيار التجريبي ($E_1, E_2, E_3, E_4$) | النتيجة المفحوصة | رجوع ولا لأ؟ (Backtrack?) | السبب والتفسير الهندسي |
| :---: | :--- | :--- | :---: | :--- |
| **1** | ($E_1 = 0$, $E_2=2, E_3=2, E_4=0$) | الحالة: $[0, 2, 2, 0]$<br>الدرجات صحيحة، لكن الاتصال فشل. | **نعم (Backtrack)** | الدرجات مطابقة لكل الجزر، لكن فحص الاتصال ($S1-06$) أظهر وجود **مكونين منفصلين** (`{A,C}` و `{B,D}`)، فرفض الحَكَم النهائي الحل. |
| **2** | $E_1 = 1$<br>($E_2=1, E_3=1, E_4=1$) | الحالة: $[1, 1, 1, 1]$<br>الدرجات صحيحة، لا توجد تقاطعات، الاتصال = 1. | **لا (تم إيجاد الحل!)** | اجتاز الفحص الجزئي والنهائي بنجاح تام (`valid = True`). هذا هو الحل الصحيح الوحيد للغز P1. |
